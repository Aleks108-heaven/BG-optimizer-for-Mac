# BG Optimizer: security and performance review

Date: 2026-10-13 (S-11 to S-13 added 2026-10-14; S-14 to S-19, the Storage tab and its hardening, added 2026-10-14; S-20 to S-23, the Drivers tab and two fixes found while building it, added 2026-10-22; S-24 to S-27, the read-only Fans tab and why it has no control, added 2026-10-22; S-28 to S-31, the read-only Battery tab, added 2026-10-22; S-32 to S-40, Administrator actions and the fixes found reviewing them, added 2026-10-27). Reviewer: the assistant that wrote the app (so this is a self-review, not independent). Machine: M1 MacBook, macOS 27.
Method: the project's own `security-checklist.md` (items 1 to 12) applied to a local app, reading the source, inspecting the built app with `codesign`, `otool`, `lsof`, and measuring CPU with `ps` and `sample`.
Automated checks you can rerun: `./BGOptimizer/tests/run.sh` (translations, log, row menu, startup items, changing jobs by hand).

## What the app can and cannot do (the attack surface)

| Question | Answer | Evidence |
|---|---|---|
| Does it listen on or use the network? | No | `lsof -i` for the running app: 0 connections. No network framework is linked (`otool -L`). No update channel. |
| Does it accept input from other programs? | No | Info.plist declares no URL scheme, no Apple events, no helper tool, no XPC service. The only input is the user's clicks. |
| Does it run as administrator, or ask for a password? | **Only if you switch on Administrator actions in Settings (off by default), and then once per change.** The app itself always runs as you. | A change is handed to macOS (`osascript ... with administrator privileges`), which shows its own password dialog and runs one fixed command as root. The app never sees or keeps the password. No entitlements, no privileged helper, no `sudo`. See S-32. |
| What can it change on other programs? | Only processes owned by the same user: put them in background mode (reversible), and switch your own LaunchAgents on or off for the next login (reversible). **With Administrator actions on and your password: switch a third-party launch daemon off or on for the next start (reversible).** | `setpriority` on same-user processes; `launchctl disable|enable gui/<uid>/<label>`; with a password, `launchctl disable|enable system/<label>` |
| What can it never touch? | System processes, security tools, local AI hosts, this app, the app in front, anything on your protected list; macOS (`com.apple.`) startup items, security tools' startup items | Covered by the automated checks in `BGOptimizer/tests/` (changing jobs by hand and startup items). |
| Third-party code? | None. Only Apple frameworks. | `otool -L` |
| Can it delete files? | Never deletes. The Storage tab moves one item at a time, after a confirmation, into the Trash (direct children of ten listed folders of your own Library). **The Drivers tab, with Administrator actions on and your password, moves one helper tool or kernel extension into a backup folder (S-32).** | `StorageAction.moveToTrash` rechecks the folder (symbolic links resolved), that the item is not a link, the leftover and in-use rules, and Observe only. 78 checks in `tests/storage_test.swift`. |
| External programs it launches? | `system_profiler` (battery health), `launchctl`, `sfltool` (read the startup list), `systemextensionsctl list` (read the system extensions), `pmset -g log` (read the power log), by full path with fixed arguments, never through a shell. **Administrator actions only: `/usr/bin/osascript`, which runs one command built from a checked name (`/bin/mkdir`, `/bin/mv`, `/bin/launchctl`, full paths) as root.** | `grep Process()` in Sources |

## Findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| S-01 | Low | The log folder, the log file and the crash-recovery file were readable by other users of this Mac (755/644). They contain the names of the programs you run. | **Fixed**: folder 700, files 600. Tested. |
| S-02 | Low | A process name or path containing a newline or escape codes could forge extra lines in the log. | **Fixed**: control characters become spaces, one entry is one line. Tested. |
| S-03 | Low | The environment variable `BGOPT_LOG_DIR` redirects where the log is written (used by the tests). | **Accepted.** Whoever can set a program's environment can already run code as you. It only changes the log location. |
| S-04 | Medium (for sharing) | The app is ad-hoc signed: no Developer ID, not notarized. On another Mac, Gatekeeper warns. | **Open.** Needs a paid Apple Developer account. Required for a warning-free download by other people; it makes no difference when the app is built on the Mac that runs it. |
| S-05 | Info | The app is not sandboxed. | **By design.** Reading other processes and setting their priority is not possible from the sandbox. |
| S-06 | Low | After checking a process, there is a tiny window before changing it in which the PID could be reused by another process. | **Mitigated**: the process identity (PID plus start time) is checked again immediately before the change. Worst case: another process of yours is put in reversible background mode. |
| S-07 | Low | Startup control: a crafted label, a file outside your LaunchAgents folder, a symbolic link, or a mismatched file could redirect a change. | **Controls in place and tested**: plain-text label only, folder check after resolving symbolic links, the file must name that exact label, macOS items, security tools and this app refused, the result is read back from launchd. |
| S-08 | Low | The text of `sfltool` and `system_profiler` is parsed. Their format is not documented and can change. | **Accepted.** Parsing is defensive: if it fails, fewer rows are shown, nothing is changed. Changes never depend on this text, they rely on `launchctl`. |
| S-09 | Medium (usability/safety) | The app was menu-bar-only with no menu bar of its own, so copy and paste did not work in its text fields and a minimized window had no app icon. | **Fixed**: a normal Dock icon and menus while a window is open (Edit, Window, View menus). Verified with the built-in window self-test. |
| S-10 | Medium (performance) | The Activity window kept refreshing while minimized or covered. | **Fixed**: refresh and row-building stop when the window is minimized, covered or closed. Verified. |
| S-11 | Medium (for sharing) | The checksum file is published next to the installer, so it detects a corrupted download but not a replaced one. | **Fixed for new releases**: the workflow signs a build record (`actions/attest-build-provenance`) for the `.dmg` when a version tag is built; check with `gh attestation verify`. Not yet used by a release: v1.0.0 predates it. |
| S-12 | Low | No hardened runtime (signature flags `adhoc` only), so another program of the same user could inject code with `DYLD_INSERT_LIBRARIES`. The app holds no permissions to inherit, so the gain is small. | **Fixed**: `build.sh` signs with `--options runtime` (flags `adhoc,runtime`). All automated checks pass with it. |
| S-13 | Low | The workflow used its actions by moving tag (`@v4`), and nothing kept them up to date. | **Fixed**: pinned by commit hash, and `.github/dependabot.yml` proposes updates weekly. |
| S-14 | Medium | **New in 1.1.0: a feature that can remove files.** A wrong path, a symbolic link or a crafted name could make it move something it should not. | **Controls in place and tested**: whole items only, directly inside one of ten fixed folders (path tricks, `..`, relative paths, a listed folder that is itself a link, links as items, control characters in names all refused); `com.apple.`, this app's files and installed security tools refused; the Trash (not delete) so it can be put back; the rules are recomputed when you press the button. |
| S-15 | Low | "Possible leftover" is a guess from a name: a settings file of a command-line tool or an app run from an odd place can be listed. | **Accepted, mitigated**: matching is by maker and also asks macOS whether an app with that identifier exists anywhere; confirmation with the reason; Trash is reversible; running makers are locked. In practice the dogfooding run listed real leftovers (see DESIGN.md section 16). |
| S-16 | Low | Between the last check and the move, the item could be swapped for a link. | **Accepted**: the Trash moves a link as a link, not what it points to, and the parent is still one of the listed folders. Same-user only. |
| S-17 | Info | The app now reads the names (not the contents) of other apps' containers, and sizes of other apps' folders in your Library. It holds no extra permission; macOS keeps container contents closed. | **By design**, no new permission requested. |
| S-18 | Low | **Found by an adversarial run on 2026-10-14.** Names with invisible or direction-changing characters (a right-to-left override, a zero-width space, a line separator) were offered in the Storage list, and could be shown or logged disguised (for example `gpj.exe` written backwards to look like a picture), or forge a line in the log. The older log rule removed only ASCII control characters. | **Fixed**: one shared `plainText` turns control, line-separator and invisible formatting characters into spaces, used for the log, process names and startup names; Storage refuses such a name outright (never offered, never moved). Tested in `log_test` and `storage_test`. |
| S-19 | Info | Memory reading (`proc_pid_rusage`) is new. | Read only, your own processes, no new permission. A process that cannot be read shows "—". |
| S-20 | Info | **New in 1.2.0: the Drivers tab** (read only when written; **see S-32 for the removal that was added later**) reads `systemextensionsctl list`, the names in `/Library/Extensions` and `/Library/PrivilegedHelperTools` (readable by any user) and the identifiers of installed apps. It can list drivers that look unused, and it cannot remove one. | **Read only by design; removal was considered and rejected.** Removing needs an administrator. This app has no privileged helper on purpose, and adding one would create the very weakness the tab inspects (a root helper reached over XPC). `systemextensionsctl uninstall` also needs SIP switched off (stated by Apple engineers on the developer forums; see DESIGN.md section 17). Checked on the development Mac: SIP on, none of those folders writable by the user, `sudo` asks for a password. |
| S-21 | Low | **Found on 2026-10-22 on the development Mac.** A security tool's name was matched as a plain substring of the whole path, so `eset` matched inside "updat**eSet**tings", "pr**eset**" and "r**eset**". Six live macOS processes were labelled "Security tool" (never slowed, their startup items and caches hidden). | **Fixed**: the name must start a word. 18 real tool naming styles still match; compared on 583 real strings (processes, startup items, cache names) the change removed 5 wrong labels and added none. Tested in `tests/policy_test.swift`. |
| S-22 | Low | **Found reviewing the new tab's code.** A version string comes from the maker's own files (a kernel extension's `Info.plist`, or the extension list) and was shown unfiltered: direction-changing characters or a huge string could be shown disguised. Same class as S-18. | **Fixed**: plain text, 40 characters at most. Tested with a hostile version. |
| S-23 | Info | "Probably not in use" is an inference, and can be wrong in two ways: the maker's app lives somewhere macOS cannot find, or another app from the same maker is installed (the match is by maker, so an orphan is missed rather than a live driver flagged). | **Accepted, by design**: nothing is changed on the strength of it. On the development Mac it flagged 2 extensions (Malwarebytes Engine and Mac Monitor: switched off, no host app found by Spotlight, bundles still in `/Library/SystemExtensions`) and correctly did not flag Adobe's helpers dated Dec 2024, whose client (Adobe Acrobat Updater) is installed. |
| S-24 | Info | **New in 1.3.0: the Fans tab** reads fan speeds from the SMC and temperatures from Apple's HID thermal sensors. **Neither interface is documented by Apple**, and the sensor calls (`IOHIDEventSystemClient*`) are in IOKit but not in its public headers. | **Read only, and no privilege.** It opens the SMC user client as an ordinary user and sends only the read-key-info and read-bytes commands (no write command exists in the code). Every value is checked before it is shown (type and length, NaN, range, min not above max); a nonsense reading is dropped, and a Mac that does not answer shows a sentence. Risk accepted: a future macOS may change or remove these interfaces; the tab would then show "no sensors" or the app would fail to start, which the finished-app start-up test in CI would show. 57 checks in `tests/thermal_test.swift`, including 300 reads with no memory growth. |
| S-25 | Info | **Fan control was considered and not built.** | An ordinary user's SMC write is refused (`kIOReturnNotPrivileged`; checked on the development Mac by writing the fan mode key with the value it already had). Control would need a root launch daemon reached over XPC, which is what S-20 rules out; with ad hoc signing it could verify its caller only by identifier. Wrong speeds can also let a Mac run hotter than macOS allows. Left as a separate, opt-in decision. |
| S-26 | Low | **Found while writing the SMC reader.** The structure passed to the SMC must be 80 bytes as in C. Swift packs the field after a nested structure into its trailing padding, so the first version was 76 bytes and every call failed with "bad argument". It failed closed (no data), not open. | **Fixed**: the nested structure is padded by hand and a test checks the size (80) and the offsets of the fields that follow (40 and 48). |
| S-27 | Info | Names of sensors come from the system, not from the user. | Cleaned with the same `plainText` rule as other external text (control, line-separator and direction-changing characters become spaces), tested with a newline and a right-to-left override. |
| S-28 | Info | **New in 1.4.0: the Battery tab** runs `/usr/bin/pmset -g log` (full path, fixed arguments, 30 s limit, never through a shell) and reads its output. The log also holds other lines that name your processes and what asked the Mac to wake (for example calendar and update daemons). | **Only lines for Sleep, Wake and DarkWake are parsed, and only the time, the battery percentage, the power source and (for a sleep) the reason are kept, in memory, for the life of the window.** The other lines are looked at for their first letter and dropped; nothing is written to disk, logged or shown. No new permission; the command needs none. |
| S-29 | Low | The log is outside input, in a format Apple does not document, and it is 5.8 MB for a week. A long, odd or hostile line must not hang, crash or mislead. | **Checked by tests** (`tests/power_history_test.swift`, 72 checks): a 17 MB text of 90,000 events (parsed in 6.5 s, limit 20), a 2 MB line with no newline, a NUL character, a percentage too large for an integer, negative or over 100, non-ASCII digits, impossible dates, a reason with a newline or a right-to-left override (cleaned with `plainText`), lines that only look like wakes (`Wake Requests`), and events out of order (never a negative length). The parser accepts a line only if it fully matches; anything else is ignored. |
| S-30 | Info | The Battery tab uses Swift Charts. | An Apple framework in the system, not third-party code; `otool -L` shows no new outside library. |
| S-31 | Info | The figures are only as good as the log. Whole-percent readings, a plug-in between two log lines, and a long power-off are not visible. | **Shown, not hidden:** short or 1 to 2 point sessions are marked "~", a rising charge is labelled and left out, a sleep that began before the log is labelled "Longer than shown", and the banner states the limits. Nothing is changed on the strength of these figures. |

| S-32 | **Medium** | **New: Administrator actions** (Settings, off by default). The app can now, for helper tools and kernel extensions marked "Probably not in use" or "Maker's app not found", move the file into a backup folder; and switch a third-party launch daemon off or on. This reverses the "no password, no helper, read only" position of S-20 and of DESIGN.md sections 15 and 17. | **Controls in place and tested** (`tests/admin_test.swift`, 43 checks, which build the command but never run it): the password goes to macOS's own dialog and the app never sees it; nothing is remembered, so each change asks again; **no privileged helper and no XPC service** (the weakness S-20 rejected is not created); the root command is built only from a name that is plain ASCII with no `/`, `;`, `$`, quotes or newline, shell-quoted and AppleScript-quoted, with full paths for every tool; the file must sit exactly one level inside `/Library/Extensions` or `/Library/PrivilegedHelperTools`, not be a link, and (kernel extension) end in `.kext`; a **system extension is never offered** (an app cannot remove one); `com.apple.`, security tools and this app are refused; a daemon change needs a plist directly in `/Library/LaunchDaemons` that names that exact label; it is **moved, never deleted**; a confirmation dialog explains it; the list is **read again** before the move; the result is read back; every step is written to the private log. **Residual risk, accepted:** the verdict is an inference (S-23), and it now has a consequence. A wrong "maker's app not found" could move a helper that something still needs. | S-35 | Low | **Found reviewing S-32.** The verdict on the screen could be minutes old when you pressed Remove (the maker's app may have been installed since). S-14 recomputes at the moment of the button; the first version of this did not. | **Fixed**: the drivers are read again after you confirm and before the password is asked, and the row must still be there, at the same path, and still be removable. **Checklist items touched by Administrator actions.** 4 (privilege): no helper, no persistent root component, root only for one command per password; the list in `/Library/PrivilegedHelperTools` is still only read unless you remove an entry. 5 (persistence): a launch daemon can be switched off or on. 9 (logging): `DRIVER`, `STARTUP` and `REFUSED` lines, in the private log, with the backup path. 14 (system extensions): never removed by the app. 11 (permissions): none new. 6 and 10: unchanged.

**Adversarial run (Storage), checklist and API-test ideas applied to a local app.** The app has no network, endpoints, accounts or tokens, so the API cases (401/403/429, schemas, headers) do not apply. What carries over is hostile and oversized input, timeouts, repeats and error leaks. Run against a stand-in home folder: a name with `%@%@%n%s` (shown literally, never used as a format), a 250-character name, combining marks, `a..b`, a leading space, an unreadable folder, a 400-level deep tree, a folder of 30,000 files (the size scan stops at its cap, 0.15 s for the whole scan), and the same item moved twice (the second is refused, nothing crashes). Errors name the item only; paths go to the private log. Checklist items 1 to 12: nothing new in 1, 2, 3, 7, 8, 9 and 12; 4 (privilege) unchanged, no helper; 5 (persistence) unchanged; 6 and 10 (integrity, supply chain) as in S-11 to S-13; 11 (permissions) no new permission asked.

**Drivers on the development Mac (2026-10-22), for the record.** The four root helpers have valid Developer ID signatures with the hardened runtime. Adobe's two helpers (version 1.2.6, signed Dec 2024) authorize only a client that satisfies their requirement pinned to Apple's anchor and Adobe's team ID, not the weak "identifier only" form. The Microsoft helpers are recent (Aug and Sep 2026). Known CVEs exist for Adobe's earlier helper (CVE-2020-9613, -9614 and -9615, per an Elastic detection rule that cites them); the fix versions were not looked up, so this review does not say that the installed build is unaffected, only that it is newer and correctly signed. No third-party kernel extensions are installed. Two switched-off system extensions have no host app (S-23); removing them is left to the user, for example with `sudo systemextensionsctl gc`, which vendor guides describe for orphaned extensions and which needs a restart. Its SIP behaviour was not verified.

Not covered: fuzzing of the parsers, a review by someone other than the author, hostile local users beyond file permissions, and the behaviour of macOS itself.

## Performance (the app's own cost, M1, 489 of the user's processes)

Measured as the process's cumulative CPU time over 20 seconds (`ps`), Observe-only mode, 12 seconds after start. 100% would be one full core. Resolution is 0.01 s, so values near 0.1% are "very small", not exact.

| State | Before the speed-up | After |
|---|---|---|
| Menu bar only (window closed) | 0.10% | 0.10% |
| Activity window open | 5.05% | 0.10% |
| Activity window minimized | 0.05% to 0.40% | 0.10% |
| Memory | | about 77 MB closed, about 101 MB with the window |

What changed: the decision for each program (is it protected? a browser?) is now remembered instead of recomputed for all processes every 5 seconds, and the disk size is read every 30 s instead of every 5 s. A profile before and after confirmed the work is still done (row building 92 ms to 21 ms, classification 71 ms to 14 ms in a 12 s sample), so the saving is real and not a stalled window. A first measurement of the minimized window with `top` read 5.3%; direct CPU-time measurement showed that was a measurement artifact.
